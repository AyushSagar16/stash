# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Build & run

```sh
./scripts/build.sh                   # debug build → ./Stash.app (ad-hoc codesigned)
./scripts/build.sh release           # release build
./scripts/package_dmg.sh             # release build + dist/Stash-<version>.dmg

swift build -c debug                 # raw SPM build (no .app bundle, won't run as a UI app)

open Stash.app                       # launch the daemon
pkill -x Stash                       # kill it
kill -USR1 $(pgrep -x Stash)         # toggle the overlay (works without Accessibility)
```

The build script wraps `swift build` with a manual `.app` bundling step (copy binary + `Resources/Info.plist` + `AppIcon.icns`) and an ad-hoc `codesign --sign -`. The codesign is load-bearing: without a stable code identity, macOS revokes Accessibility/Notification grants on every rebuild. There are no tests in this repo.

## Architecture

Stash is a single-target SwiftPM macOS executable (`Package.swift`, swift-tools 6.0, macOS 14+, language mode v5) bundled into `Stash.app`. `Resources/Info.plist` sets `LSUIElement=true`, so the process runs as an accessory daemon — no Dock icon, no menu bar item, no visible scene at launch (`StashApp.swift` returns `Settings { EmptyView() }`).

**Lifecycle is driven by `AppDelegate.applicationDidFinishLaunching`**, which wires up every subsystem in a fixed order: `NSApp.setActivationPolicy(.accessory)` → `LaunchAgent.registerForLaunchAtLogin()` → open `TaskStore` (fatal if it fails) → start `NotificationScheduler` / `PromotionTimer` / `HistoryPruner` → build `OverlayPanel` with a SwiftUI `ContentView` host → install `HotkeyMonitor` → register a `SIGUSR1` `DispatchSource` that toggles the panel.

### Layered structure (`Sources/Stash/`)

- **`Window/`** — `OverlayPanel` is a `.nonactivatingPanel` borderless `NSPanel` at `popUpMenuWindow` level with `canJoinAllSpaces`/`fullScreenAuxiliary`. It anchors its top edge ~22% from the top of the visible screen on each `show()` and grows downward as SwiftUI reports new fitting sizes via `adopt(contentSize:)`. `HotkeyMonitor` detects double-Control by watching `.flagsChanged`/`.keyDown` through both global and local `NSEvent` monitors; the global monitor needs Accessibility permission and the install path triggers the system prompt with `AXIsProcessTrustedWithOptions(prompt: true)`. Any non-Control key pressed between the two taps invalidates the chord (`keysSeenSinceControlPress`).
- **`Model/`** — `StashTask` is a `@Model` (SwiftData). `TaskStore` is `@MainActor` and owns the `ModelContainer` rooted at `~/Library/Application Support/stash/Stash.store`. **Important constraint:** SwiftData's `#Predicate` runtime rejects captured enum values, so `StashTask` stores `tierRaw: String` and `statusRaw: String` instead of the `Tier`/`TaskStatus` enums directly, and exposes typed `tier`/`status` accessors via extension. All predicates inside `TaskStore` (`openTasks`, `clear(tier:)`, `l2DueForPromotion`, `donePruneCandidates`) compare against captured raw-string locals — **do not** introduce predicates that capture enum values, they will trap at runtime. IDs are 3-char hex prefixes generated by `makeUniqueId()` with up to 64 collision retries before falling back to a UUID slice.
- **`Commands/`** — `CommandParser.parse(raw, defaultTier:)` returns a `Command` enum. Bare text becomes `.add` at the active default tier; reserved verbs (`done`, `mv`/`move`, `rm`/`del`/`delete`/`remove`, `find`/`search`) route to typed cases. Inline `@time` (e.g. `@4pm`, `@5:30am`, `@tomorrow`) and `#tag` are stripped from the title in `parseAddArgs`. `CommandRunner` (also `@MainActor`) executes parsed commands against `TaskStore` and schedules/cancels notifications side-effectfully. Errors are surfaced via `CommandError` and rendered through `CommandResult.message`.
- **`Services/`** — `PromotionTimer` runs a 60s `Timer` that promotes any L2 task whose `dueAt` falls within the next hour into L1 (`store.l2DueForPromotion()` → `store.move(_:to: .L1)`). `HistoryPruner` deletes completed tasks older than 7 days. `NotificationScheduler` requests `UNUserNotificationCenter` authorization and schedules/cancels per-task local notifications. `LaunchAgent` wraps `SMAppService.mainApp` for launch-at-login — it only persists across reboots when the bundle lives at a stable path (e.g. `/Applications/Stash.app`); from `.build/...` it logs "registered" but the agent points at a path that gets overwritten on the next build.
- **`Views/`** — SwiftUI tree under `ContentView`: `CommandLineView` (input field with Tab autocomplete, ↑/↓ history) plus `TierSectionView`/`TaskRowView` for the always-visible L1/L2/L3 lists. The host is a `StashHostingController<ContentView>` so the panel can resize to its contents.
- **`Theme/Palette.swift`** — color tokens.

### Tier semantics

`Tier` (`Model/Tier.swift`) defines the tier system used everywhere: L1 (next hour, default 1h `dueAt`), L2 (next 3–5h, default 5h `dueAt`), L3 (no due date). `defaultDueOffset` is what the auto-promotion timer relies on — when an L2 task's due time crosses into the next hour, `PromotionTimer` slides it into L1. Tasks added without an explicit `@time` get their `dueAt` from `tier.defaultDueOffset` in `StashTask.init`.

### Logging

All subsystems log to `OSLog` under subsystem `com.stash.app` with per-component categories (`AppDelegate`, `Hotkey`, `Panel`, `TaskStore`, `Promotion`, `LaunchAgent`, `CommandRunner`, …). To inspect at runtime:

```sh
log show --predicate 'subsystem == "com.stash.app"' --info --last 5m --style compact
```

## Versioning & release

`CFBundleShortVersionString` in `Resources/Info.plist` is the single source of truth. `package_dmg.sh` reads it via `PlistBuddy` and produces `dist/Stash-v<version>.dmg`. The DMG is unsigned/un-notarized — first launch on another machine requires right-click → Open.
